# MP4 배경 자동 분리

처음 사용한다면 **Tools → Video to Unity → 영상으로 이펙트 만들기**에서 영상 드래그부터 씬 추가까지 진행하세요. [한 창 사용법](QuickWorkflow.ko.md). 아래는 세부 설정용 고급 창 안내입니다.

알파가 없는 영상을 분석해 투명도를 만들고, 기존 VideoEffectAsset으로 저장한다. 게임 실행 중에는 AI나 배경 분석을 실행하지 않는다. 개발 PC에서 한 번 처리한 결과를 기존 VideoPlayer와 합성 셰이더로 재생한다.

## 사용 순서

1. **Tools → Video to Unity → 고급 → MP4 배경 분리**를 연다. 기존 이펙트 만들기 창에서도 진입할 수 있다.
2. 원본 파일과 FFmpeg·ffprobe 실행 파일을 선택하고 분석한다.
3. 제안된 배경색과 신뢰도를 확인한다. 자동 감지가 불확실하면 **검정 배경 사용**·**초록 배경 사용** 버튼으로 수동 색을 정한다. 미리보기를 만든 뒤 **원본에서 배경색 찍기**를 켜고 원본을 클릭해 색을 고를 수도 있다.
4. 서로 다른 시간에서 원본과 체커보드 결과를 비교한다. 문턱값·부드러움과 가장자리 연결 옵션을 조정한다.
5. 남길 검정 글자·배너가 있으면 보호 사각형을 추가한다. 결과 화면에서 끌거나 X·Y·W·H 수치로 편집한다. 최대 64개이며 프리셋을 바꿔도 유지된다.
6. 새 영상과 새 이펙트 에셋의 저장 경로를 정하고 변환한다. 완료된 에셋으로 기존 화면·UI·월드 배치 흐름을 이어간다.

원본은 보존하며 기존 출력 파일을 덮어쓰지 않는다. 변환 취소, 창 닫기, Play Mode 진입과 에디터 종료에서는 진행 중인 작업을 취소한다. FFmpeg와 ffprobe는 별도로 준비해야 하며 Python·AI 모델 설치는 필요 없다.

설정·시간·보호 영역을 바꾸면 이전 미리보기라는 안내가 나타난다. **미리보기 새로고침**으로 최신 결과를 확인한 다음 저장한다. 자동 신뢰도 60% 미만은 자동 변환을 거부하며, 수동 색 선택 후에는 미리보기로 판단한다.

## 제거 방식

자동 감지는 여러 시간대에서 화면 테두리의 색을 모아 일관된 색을 제안한다. 이 신뢰도는 **테두리 색의 일관성**이다. 그 색이 작가가 지우려던 배경이라는 의미까지 판단하지는 않는다. 화면 전체를 차지하는 단색 물체도 배경으로 오인할 수 있으므로 미리보기를 확인한다.

**가장자리와 연결된 배경만 제거**하면 같은 색이라도 다른 물체로 둘러싸인 내부 영역은 유지한다. 예를 들어 밝은 테두리 안의 검정 글자·그림을 보존할 수 있다. 배경과 연결된 검정 그림에는 보호 영역이 필요할 수 있다. 모든 같은 색 제거로 바꾸면 물체 내부의 해당 색도 제거한다.

보호 영역은 원본 기준 왼쪽 위가 (0,0), 오른쪽 아래가 (1,1)인 사각형이다. **영상 전체에서 위치가 고정**되며 움직이는 물체를 추적하지 않는다. 물체가 나타나기 전이나 사라진 뒤에도 영역 안의 배경이 남을 수 있으므로 시작·끝 장면까지 확인한다.

프레임 간 안정화는 거의 움직이지 않는 경계의 작은 색 변화만 완화한다. 새로 나타난 배경과 움직이는 경계는 현재 프레임을 우선한다. 한 프레임만 보는 미리보기에는 이전 프레임이 없으므로 이 보정은 전체 변환에서 확인한다.

## 출력과 제한

- Packed H.264는 좌 RGB·우 알파, Native Alpha WebM은 실제 알파로 저장한다. 새 에셋에 모드·원본 크기·Straight RGB 설정을 자동 적용한다.
- 흰색·회색 알파의 숫자는 투명도 데이터다. RGB는 sRGB 기준으로 배경색 혼합을 풀어 Straight로 저장한다. 투명 경계의 색은 추정치이며 원래 제작 레이어의 복원이 아니다.
- 현재 대상은 고정 프레임 간격(CFR), 짝수 해상도, 정사각형 픽셀, 프로그레시브 SDR 영상이다. VFR·회전 메타데이터·HDR 등은 설명과 함께 거부한다. 오디오는 제거한다.
- 이미 투명 픽셀이 있는 MOV/WebM은 기존 알파를 손상하지 않도록 거부한다. **영상 이펙트 만들기 → 알파 원본 변환**을 사용한다. 알파 채널이 있어도 모든 픽셀이 불투명한 영상은 처리할 수 있다.
- Packed H.264는 원본의 정수 시간 단위로 프레임 간격을 유지한다. Alpha WebM은 컨테이너의 밀리초 단위 오차가 있다. Open-GOP 영상은 정확한 프레임을 얻기 위해 처음부터 디코딩할 수 있어 긴 영상의 분석·미리보기가 느려질 수 있다.
- 연기·빛 번짐·모션 블러와 배경색이 섞인 부분은 조정이 필요하다. 복잡한 배경의 의미 기반 AI 분리나 자동 물체 추적은 포함하지 않는다.
- 처리 중에는 중간 알파 영상과 검증 데이터의 임시 공간이 필요하다. 긴 고해상도 영상은 처리 시간과 저장 공간이 증가한다. 게임에서 많은 영상을 동시에 재생하는 비용도 별개다.

정확한 검정 그림과 투명 경계를 보존할 수 있는 제작 원본이 있다면 **ProRes 4444 · RGB+Alpha · Straight** 경로를 우선한다. 이 기능은 이미 합쳐진 MP4를 활용하기 위한 보조 도구다.
